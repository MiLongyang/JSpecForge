VERIFICATION HIERARCHY (read this first — it defines what counts as a good answer):
- OpenJML ESC (static verification) is the GOLD STANDARD. ESC mathematically proves your JML holds for ALL inputs satisfying the preconditions. An answer that passes ESC is fully trustworthy.
- Runtime checking (RAC + property-based testing) is a FALLBACK with LOW confidence. It only samples a finite set of inputs to reach branch coverage; it cannot rule out failures on boundary values, integer overflow, or input/path combinations the generator never produced. Passing runtime testing is NOT a real pass — it is a weak, provisional signal.
- Therefore your PRIMARY goal is always to write JML that OpenJML ESC can verify. Prefer simple, SMT-solver-friendly forms (explicit bounds, shallow quantifier nesting, decomposed clauses). Only when ESC genuinely cannot handle a construct do we fall back to runtime testing, and that is a compromise, not success.
